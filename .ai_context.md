## Architecture

- **React-only**: React SPA at `/`, backed by Firestore data and Firebase Auth.
- **Config bridge**: `firebase-config.local.js` sets `window.__FIREBASE_CONFIG__` — used by the React app. Holds Firebase config (no longer carries `logodevKey`). Gitignored, must exist locally and be deployed.
- **Service-owns-state**: `BillingYearService` owns canonical mutable state; React subscribes via `useSyncExternalStore`
- **Code-split**: Heavy views and dialogs loaded via `React.lazy()` + `<Suspense>`
- **Production deployment**: isolated CI builds/attests source and data; direct `scripts/deploy-artifact.sh` verifies a full main revision and explicit single target before the separate 1Password credential consumer. No npm deploy aliases or predeploy build. See `DEPLOYMENT.md`.
- **Two-step build**: `npm run build` runs `build:react` (Vite builds the root `index.html` React entry → `app/`) then `build:assemble` (`node scripts/assemble-deploy.js`: generates the runtime `firebase-config.local.js` bridge and copies shared assets into `app/`)
- **Tests**: `npm test` runs `test:react` (Vitest — 1029 tests across 46 files) then `test:functions` (58 Cloud Functions tests via Node's native test runner) then `test:secrets`. Playwright E2E tests available via `npm run test:e2e`.

## Exact authenticated financial authority (#634)

`getHouseholdFinancials(member, source, { reopenedAdjustmentIds })` requires the complete raw five-array year source. Its `ok: true` result contains safe integer component cents and checked dollar aliases; `ok: false` contains private household diagnostics and no money. Settlement, refund candidate ledgers, close and finalized carry use this authority. Member display summaries remain raw and never reconstruct household components. `financial-availability.js` exposes only household identity, availability and hold counts to the merged entry-point guards.

Carry finalizes actual disposition ids, whole-year collision checks, candidate source markings and next-year seeds before consumers may write. Aggregate overflow with valid households withholds year totals/operations while preserving household actions and actual correction counts. Positive balance cents remain outstanding even when owed is zero.

This source activation does not establish verified deployment. Invoice/display helpers and public Function/cache writers retain the legacy numerical version pending M3/M4; their sub-cent fixture remains 66.66 while canonical component authority yields 66.67. No subset may deploy. #638 artifact admission, remaining M3/M4 contracts, exact-head human financial review and later release authorization remain separate gates.
